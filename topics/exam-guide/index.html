The Claude Certified Architect (Foundations) exam is scenario-based multiple choice across five weighted domains. It rewards deterministic solutions over probabilistic ones when stakes are high, proportionate fixes over over-engineering, and tracing failures to their root cause. This page maps the domains and points each one at the questions in our banks.

Agentic Architecture & Orchestration

The agentic loop is driven by stop_reason: tool_use means run the tool, append results, call again; end_turn means done. Multi-agent topology is hub-and-spoke: all communication flows through the coordinator, and subagents never share memory, so every piece of context must be passed explicitly in the prompt.

  • Spawn subagents with the Task tool; the coordinator's allowedTools must include Task. Emit parallel Task calls in one response for speed.
  • When stakes are financial, security, or compliance, enforce tool ordering programmatically with hooks and prerequisite gates, not prompt instructions.
  • Trace missing-subtopic failures to the coordinator's task decomposition, not downstream agents.

Tool Design & MCP Integration

Tool descriptions are the primary mechanism Claude uses for tool selection. The first fix for misrouting is better descriptions, not few-shot examples, a routing classifier, or tool consolidation. Scope each subagent to about 4 to 5 role-relevant tools.

  • Know tool_choice cold: auto (may return text), any (must call one), forced (must call a named tool).
  • MCP isError with four categories: transient, validation, business, permission. An access failure is not a valid empty result.
  • Project .mcp.json is shared and version-controlled with ${ENV} expansion; user config is personal. Grep searches contents, Glob matches paths.

Claude Code Configuration & Workflows

The CLAUDE.md hierarchy has three levels: user (personal, not shared), project (version-controlled, shared), and directory. The favorite trap is a teammate missing instructions because they live in user-level config. Path-specific rules in .claude/rules/ with glob frontmatter apply across the whole codebase where directory-level files cannot.

  • Skill frontmatter: context: fork isolates verbose output, allowed-tools restricts tools, argument-hint prompts for parameters.
  • Plan mode for large, multi-file, architectural work; direct execution for clear single-scope changes.
  • CI/CD: -p for non-interactive mode (or the job hangs), --output-format json with --json-schema for parseable findings, an independent instance for review.

Prompt Engineering & Structured Output

Be explicit. Vague instructions like "be conservative" do not work; define exactly which cases to report versus skip with concrete examples. Few-shot examples (2 to 4, each showing reasoning) are the highest-leverage consistency technique.

  • tool_use with JSON schemas eliminates syntax errors but not semantic errors. Nullable fields prevent fabrication.
  • Validation-retry works for format and structure errors, not for information genuinely absent from the source.
  • Message Batches API: 50% savings, up to 24h, no latency SLA, no multi-turn tool calling. Batch overnight work, keep blocking checks synchronous.

Context Management & Reliability

Progressive summarization destroys transactional data. Keep a persistent "case facts" block in every prompt and never summarize it. Models miss content buried in the middle of long inputs, so place key summaries at the start.

  • Valid escalation triggers: explicit human request (honor immediately), policy gaps, inability to progress. Sentiment and self-reported confidence are unreliable triggers.
  • Error propagation: return structured context (failure type, attempted query, partial results, alternatives). Never silently suppress or kill the whole workflow.
  • Aggregate accuracy hides per-type failures. Validate by document type and field, calibrate confidence on labeled sets, and carry provenance through synthesis.

Reject on sight

  • Parsing natural language to decide when an agent loop should stop. Use stop_reason.
  • Arbitrary iteration caps as the primary stopping mechanism.
  • Checking for assistant text as a completion signal (text can accompany tool_use).
  • Assuming subagents share memory with the coordinator. They do not.
  • Prompt-only enforcement for financial, security, or compliance-critical logic. Use hooks and gates.
  • Few-shot examples, routing classifiers, or tool consolidation as the first fix for tool misrouting. Fix the descriptions first.
